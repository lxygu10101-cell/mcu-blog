## 从输入时钟开始

计算前先确认送到定时器的实际时钟 `fTIM`。不要直接把 CPU 主频填进去：具体来源与芯片系列、时钟树和分频设置有关。以芯片参考手册和 CubeMX 时钟树为准。

以下讨论使用内部时钟、向上计数、无额外重复计数的常见情况。中心对齐、外部时钟、重复计数器等模式需要按对应配置重新计算。

## 两个加一从哪里来

预分频器 PSC 将输入时钟除以 `PSC + 1`。计数器从 0 数到 ARR，包含起点，因此共计 `ARR + 1` 个计数周期。

```text
fCNT    = fTIM / (PSC + 1)
fUPDATE = fTIM / ((PSC + 1) × (ARR + 1))
```

假设实际定时器输入时钟为 72 MHz，将 PSC 设为 71：计数时钟为 1 MHz，每个计数周期为 1 μs。ARR 设为 999，则每 1000 μs，也就是 1 ms 产生一次溢出更新，对应 1 kHz。

| 参数 | 示例值 | 含义 |
| --- | --- | --- |
| fTIM | 72 MHz | 假定的实际输入时钟 |
| PSC | 71 | 分频系数为 72 |
| ARR | 999 | 每次更新经过 1000 个计数周期 |
| 更新周期 | 1 ms | 对应更新频率 1000 Hz |

## 更新频率不等于所有输出频率

如果每次中断仅翻转一次 LED 电平，一个完整的高低电平周期需要两次中断。此时输出方波频率是中断频率的一半。

同时，PWM 输出还涉及对齐方式、CCR、极性和其他设置。本站工具箱的定时器工具计算的是上述条件下的更新频率，不将它直接称为所有模式下的 PWM 频率。

## 调试时保留证据

先以一个容易观察的慢周期运行。用示波器或逻辑分析仪测量一个专门用于调试的引脚，记录输入时钟、PSC、ARR 与测量结果。修改参数后，核对预装载与更新事件何时生效。

计算前还应检查定时器位宽：16 位 ARR 最大为 65535，32 位最大为 4294967295，具体支持情况取决于芯片和定时器实例。
